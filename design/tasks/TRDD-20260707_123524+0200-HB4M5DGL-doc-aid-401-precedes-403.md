# TRDD-HB4M5DGL — Document the 401-before-403 self-modification auth ordering

## Problem

`PATCH /api/agents/[id]` with an `X-Agent-Id` self-claim header and no Bearer token
returns HTTP 401 (authentication), not 403 (authorization). A reader of the governance
docs, or a plugin author expecting a 403 "you cannot modify yourself" signal for any
rejected self-modification attempt, will be surprised by the 401.

**Evidence (SCEN-003 S037, 2026-06-23 run):** the response body was `{"error":"Agent
identity requires authentication. Include Authorization: Bearer <api-key> header."}`
with HTTP status 401. No mutation occurred — the target agent's label was verified
unchanged after the attempt.

## Root cause

This is correct, intentional defense-in-depth, not a code defect: AID proof-of-possession
(Bearer-token authentication) gates the route BEFORE the no-self-modification AUTHZ rule
runs. It is a documentation gap, not a code gap. Verified 2026-07-07: no note about this
401-precedes-403 ordering exists in `docs/GOVERNANCE-RULES.md`, and no local
`agent-identity` skill file exists in this repo to carry the note either (that skill ships
from the `ai-maestro-plugin` repo, outside this repo's scope).

## Proposed fix

Add a short note to `docs/GOVERNANCE-RULES.md` near the no-self-modification rule
(the rule governing `PATCH /api/agents/[id]` self-claim rejection):

> An unauthenticated self-modification attempt is rejected at the AUTH layer with 401
> (Bearer token required) before the no-self-modification AUTHZ rule (403) is ever
> reached. Both outcomes block the mutation — callers should treat 401 and 403 as
> equally conclusive "rejected" signals for this route, not assume 403 is the only
> valid rejection code.

Because the `agent-identity` skill lives in the separate `ai-maestro-plugin` repo (per
`~/.claude/rules/how-to-fix-issues-of-other-projects.md`, cross-repo changes go through
that repo's own issue/PR flow, not a direct edit from this repo), file a companion
GitHub issue on `Emasoft/ai-maestro-plugin` requesting the same note be added to the
`agent-identity` skill's SKILL.md, rather than editing that repo directly from here.

## Verification

companion `Emasoft/ai-maestro-plugin` issue is filed and linked from this TRDD's

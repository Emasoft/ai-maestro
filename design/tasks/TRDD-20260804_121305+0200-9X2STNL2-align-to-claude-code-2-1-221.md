## Problem

Claude Code shipped ~16 releases of behaviour changes since this repo's agent/plugin/hook/settings
surfaces were last reviewed against it. Several of them change SEMANTICS of things already
committed here rather than adding opt-in features — a permission rule that used to match now
matches differently, a subagent spawn depth that was 1 is now 3, a `mode:` parameter that used to
mean something is now ignored. Those do not fail loudly; they change what the committed config
DOES.

## Candidate surfaces — ALL UNVERIFIED, measure each first

Ordered by "changes existing behaviour" before "adds a capability", because the first class is the
one that silently invalidates what is already committed.
